# Hearing repair plan

Root cause CONFIRMED (reproduced 07:25:20.401 → 07:25:21.804):
ONE physical press delivered twice — Electron globalShortcut (X11 grab,
instant) + GNOME media-keys command (~500-900ms later) → second delivery
stops capture → whisper on 0.5s of audio → "no speech". The 300ms in-host
debounce cannot bridge a cross-process gap.

## Steps
- [ ] A. Single press owner: daemon reports gnome binding; pet-host skips
      Electron registration when GNOME owns delivery; periodic re-sync.
- [ ] B. Diagnostics: first-pcm, voice-detected, last-voice, stop reason,
      byte counts, transcription ms — action ledger only, no mic contents.
- [ ] C. `hearing` state + adaptive voice-end detection:
      listening → hearing (first real PCM) → transcribing; noise-floor
      calibration, hysteresis, 1.6s sustained silence after speech,
      manual stop without speech = honest no-speech, timeout submit.
- [ ] D. Renderer: hearing sprites (3 frames), waveform bars driven by
      real RMS level stream (throttled), indicator phases.
- [ ] E. Dashboard: hearing indicator + level bar (same backend state).
- [ ] F. Tests for every behavior above.
- [ ] G. Live checks: real hardware mic capture (ambient), capture
      lifecycle, cleanup. Human-speech recognition = NOT VERIFIED (user).

Constraints: no push; no second pet; no new STT provider; keep music
router; honest reporting everywhere.
